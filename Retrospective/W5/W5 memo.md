## 5주차 메모

mapreduce는 각 작업이 새로운 job이라서 똑같은 데이터 자꾸 쓰고 읽고 해서 heavy io 일어남

RDD로 해결

immutable, distributed, in memory across stages

계산 과정?을 lineage로 남기고, rdd 캐시 못찾으면 rdd 조상으로부터 복구

사실 이해 잘 못했는데 복습해야겠다

Action: 값이 나와야 하는거, 액션 하나를 잡 하나라고 생각

Transformation: 데이터 자체에 변화를 주는 거

- Narrow: 생각하는거 대부분

- Wide: 큰 덩어리 나오는거, 셔플도 일어나고 I/O 많음
  - groupBy, reduceByKey, join 등

Narrow로 바꿀 수 있으면 바꾸는게 좋다.

Lazy evaluation 하면 명령을 즉시 한줄씩 하지 않아서 싼 계산부터 먹일 수 있다, 즉 optimize 가능함

태스크는 파티션 위에 붙이기만 하면 되는거라 우리는 파티션을 어디에 어떻게 나눠뒀는지 생각하는게 중요

스테이지: 셔플 기준으로 나눠진 단위, 셔플까지 해서 넘김. 받으면 바로 작업 할 수 있게
